## 2025-05-15 - Prisma Column-to-Column Comparison Limitation
**Learning:** Prisma (v6.x) does not support comparing two columns of the same record directly within a `findMany` `where` clause (e.g., `stock: { lte: Prisma.inventoryItem.fields.minStock }` is not supported in this version). Performing this filtering in-memory (`.filter()`) after fetching all records is a major performance anti-pattern that leads to O(N) data transfer and memory usage.
**Action:** Use `prisma.$queryRaw` to fetch only the IDs of the records meeting the criteria using raw SQL (which *does* support column comparison), then use those IDs in a standard `findMany({ where: { id: { in: ids } } })` call. This maintains the benefits of Prisma's `include` and type safety while delegating the filter to the database.
